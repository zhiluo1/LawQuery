## 2. A2 中国政府网·政策文件库(GOV_CN,原生解析)

### 2.1 检索接口(公开 JSON,M0 实测)

```
GET https://sousuo.www.gov.cn/search-gov/data
    ?t={type}            zhengcelibrary_gw=国务院文件(含国令/行政法规);zhengcelibrary_bm=部门文件
    &q={keyword}         空关键词 + sort=pubtime 可按日期浏览(分类列表页用法)
    &p={page}            页码,从 1 开始
    &n={pageSize}        每页条数(应用内取 10~15,上限 50)
    &sort={score|pubtime} 相关度 / 发布时间倒序(2026-10-04 实测 publishdate 等效)
    &timetype=timeqb     时间范围:全部
    &pubtimeyear={year}  可选,按年份过滤
    &puborg={org}        可选,按发文机关过滤(部门文件库)
```

**响应结构(M0 实测)**:顶层 `{code, msg, data, searchVO}`;条目列表在 **`searchVO.listVO`**
(代码同时兼容顶层 `listVO` 兜底,按 id 去重)。

条目字段映射:

| 接口字段 | 含义 | 映射到 LawRef |
|---|---|---|
| `id` | 源内唯一 id | `id` |
| `title` | 标题(可能含高亮标记,以 Jsoup 纯文本化) | `title` |
| `pcode` | 发文字号,如「国令第843号」 | `docNumber` |
| `ptime` / `pubtimeStr` | 发布时间(毫秒时间戳 / `2026.08.13`) | `publishDate` |
| `url` | 详情页绝对地址 | `url` |
| `fwdw` | 发文单位(部门文件时有值,否则按「国务院」兜底) | `issuingAuthority` |
| `childtype` | 文件类型(国令/国发/国函/国办发…) | 仅展示,不入库 |

> 分页说明:接口未返回精确游标,应用以「page+1 且仍有数据」作为续翻条件,返回空页即停止。

### 2.2 详情页(HTML)

- 元信息:`table.bd1` 内 `<td><b>键：</b></td><td>值</td>`,键含全角空格
  (索 引 号 / 主题分类 / 发文机关 / 成文日期 / 标　　题 / 发文字号 / 发布日期),解析时归一化;
- 正文:`#UCAP-CONTENT > div.trs_editor_view > <p>`(兜底:`.pages_content` → `body`);
- 章节条:`第X编/章` `第X节` `第X条` 正则逐段识别,中文条号换算阿拉伯数用于条号直达;
- 施行日期:从正文「自YYYY年M月D日起施行」提取;
- 结构缺失时降级为纯文本 + 「查看原文」(需求 M4 容错,单测覆盖);
- 测试快照:`app/src/test/resources/samples/gov_detail_790.html`(国令第790号)、`gov_search.json`。

## 3. A3 最高人民法院(COURT,原生解析)

**分类归属(2026-10-08)**:接入「**司法解释**」分类,与 flk 的司法解释系列并列
(**不新增分类入口**)。无关键词浏览时抓「司法解释」栏目,列表页按**来源分组**展示
(见第 9 节);有关键词时走官方站内检索。详情走原生解析,在应用内直接读正文。

- 司法解释栏目:`GET https://www.court.gov.cn/fabu/gengduo/16.html`(司法文件为 `17.html`);
  翻页:`16_2.html`、`16_3.html`…(页面「下一页」链接);
- **搜索(2026-10-08 更正)**:有关键词走官方**站内检索**
  `/search.html?content=<URL编码关键词>&page=N`(服务端渲染结果页,官方会做**正文匹配**
  并按其相关度排序,M0 实测快照 `court_search.html`)。
  ⚠️ **不能**逐条按标题过滤:只在正文命中的结果(如搜「劳动合同」命中《关于审理劳动
  争议案件适用法律问题的解释》,标题里没有「劳动合同」)会被整片误杀,用户感知即
  「官网搜得到、这里搜不到」。实现仅在「整页一条标题都不命中」(说明检索接口降级
  成了栏目列表)时才按标题重筛,见 `CourtSource.applyTitleFallback`(单测锁定)。
  (旧版实现为「拉栏目第一页 + 标题本地过滤」,请求量虽小但检索能力受限,已废弃。)
- 详情:`div.detail > div.title`(标题)、`div.detail_mes li`(`来源：…`、`发布时间：YYYY-MM-DD hh:mm:ss`)、
  正文 `div.txt_txt > <p>`;测试快照:`court_sjs_list.html`、`court_sjs_detail.html`。

## 4. A1 国家法律法规数据库(FLK,原生解析)

> **2026-10-06 起由「仅官方直通」改为原生解析供数**(`data/source/FlkSource.kt`):
> 六个法规分类(宪法/法律/行政法规/监察法规/司法解释/地方性法规)的题录与筛选
> 均由官方检索接口直接取数,免登录、无付费墙,装上即可用。
> 正文仍在应用内打开**官方阅读器**呈现 —— 官方阅读器接口不下发可抽取的文字
> (`/reader/text` 的 `areas` 恒空,已用抓包证实),因此不本地解析正文。
> 原先那张「在国家法律法规数据库中搜索『x』」的中间跳转卡片已随之移除(直通源不再注册)。

- 官方对第三方**开放的检索端点**为本应用唯一取数通道:不批量爬取、不缓存正文
  (每次查看实时取自官网),访问节律见第 6 节;
- 搜索深链(M0 未能以静态方式确认 JS 路由行为,按历史版本格式实现):
  `https://flk.npc.gov.cn/fl.html?type=&searchType=title%3Bvague&q={URL编码关键词}`;
  分类深链:`type=xf|flfg|xzfg|jcfg|sfjs|dfxfg`(宪法/法律/行政法规/监察法规/司法解释/地方性法规);
  **若真机实测深链未自动带入关键词,兜底方案已实现**:WebView 壳底部提供「复制搜索词」按钮,用户在官方页面内粘贴;
- **筛选下推三维度**(`POST /law-search/search/list`):`zdjgCodeId`(制定机关)、
  `sxx`(时效性)、`gbrqYear`(公布年份)。界面上的「地区」与「发文机关」共用同一个
  `zdjgCodeId` —— 地方性法规只开地区维度、其他分类只开机关维度,二者不会同时有值。
  ⚠️ 2026-10-08 修:此前**只下推了地区**,发文机关从未下发,于是「按发文机关筛选」
  退化成「在已加载的几十条里做客户端过滤」—— 用户要不停往下翻,结果和数量才对得上。
  现由 `FlkSource.zdjgCodeOf(region, authority)` 统一取 `resolve(region) ?: codeOf(authority)`;
  机关名必须能在 `FlkAuthorities` 表里查到才下发,查不到就不下推(宁可不过滤,也不发脏值)。
- 深链集中定义于 `ui/web/DeepLinks.kt`,白名单于 `ui/web/UrlWhitelist.kt`(需求 7.4)。

## 5. UA 策略(逐源注明,需求 4.1 / 7.2.2)

| 通道 | UA | 理由 |
|---|---|---|
| A2/A3 原生解析 | `Mozilla/5.0 (Linux; Android {ver}; {model}) AppleWebKit/537.36 … Chrome/126 … Mobile Safari/537.36 LawQuery/1.0.0` | M0 实测上述接口对无浏览器特征的请求同样返回数据,但 gov.cn 历史页面对异常 UA 存在风控;浏览器兼容形态 + **如实追加应用标识**是兼容性与"UA 如实标识"的平衡,不伪造 Cookie、不轮换 IP |
| WebView 直通 | 系统 WebView 默认 UA(不覆盖) | App 等同浏览器角色(需求 3.1.4),不注入、不篡改 |

## 6. 访问节律(需求 7.2.3 / 项目文档 4.1)

- 全局并发 ≤ 2(`ThrottleInterceptor`,单测覆盖);
- 同一源两次请求间隔 ≥ 2s(单测覆盖);
- 5xx/超时:2s 退避后重试至多 1 次;4xx 不重试;403/429:立即停止该源请求并冷却 10 分钟(单测覆盖,验收 E3);
- 不配置 OkHttp 磁盘缓存;请求头 `Cache-Control: no-cache`(需求 6.1)。

## 7. 公安部规章库(MPS_REG,原生解析)

归入**国务院及部委文件**分类,与 A2 中国政府网(国务院文件/部委政策文件)并列;
免登录、无付费墙,装上即可用。

### 7.1 检索接口(JSONP,2026-10-07 实测)

```
GET https://app.mps.gov.cn/gdnps/zc/searchIndex.jsp
    ?callback=cb
    &goPage={页码}&pageSize={每页条数}
    &zhengce=1
    &ownSubjectDn=/1/2257048/7387898/8244390/8244395   <- 叶子节点才可命中数据
    &title={标题关键词}&content={正文关键词}
```

- 返回体是 **JSONP**:外层包着 `cb({...});`,已在外壳处理环节剥壳;
- `title` 与 `content` 二者**互斥**(官网用「标题/全文」单选按钮切换),
  一次只能命中其一 —— 应用按「先标题、后正文」各发一次并去重,天然实现名称优先;
- `ownSubjectDn` 必须是叶子节点。父节点下推一律返回 0 条(与 flk 分类 codeId 同样的坑);
- 不传 `yxx=yxx1` 时也会带上已废止规章,`yxx` 字段本身才是时效判据(`是`/`否`);
- 默认排序已是发布日期倒序,无 sort 参数(日期区间筛选等高级条件官方未提供可用参数)。

### 7.1.1 分页(2026-10-08 实测)

| pageSize | 官方自报 totalPageNum | 说明 |
|---|---|---|
| 15(界面统一窗口) | 5 | 首屏只出 15 条,用户以为「只有 15 部」 |
| **50(本源固定)** | **2** | 全库 63 条 → 两次请求取全,页间不重复 |

- 本源**固定按 50 取页**(`MpsRegSource.MPS_PAGE_SIZE`),不跟随界面的 15 ——
  flk 之外的本源页容量本就是各自的事,只有这样才既少打扰风控站点、又让首屏基本覆盖全库;
- 下一页仍以官方 `totalPageNum` 为准(不是靠本页条数猜)。

### 7.2 详情(同一接口按 id 取单条)

```
GET https://app.mps.gov.cn/gdnps/zc/searchIndex.jsp?callback=cb&goPage=1&pageSize=20&id={条文主键}&zhengce=1
```

**列表里的 `htmlContent` 恒为空串**,带上 `id` 再请求一次才带上正文 HTML。
正文中 `<br>` 是换行、`<p>`/`<div>` 是段落,`MpsRegContent.toBlocks` 按此还原。

⚠️ **正文 HTML 开头常带一份「目录页」**(每章一行,如 `第一章 总则`),正文里又会出现
同样含义的章标题(`第一章 总 则`,字内多空格)。逐条建章会得到「一半是空章」的目录
+ 正文两份章节,用户展开前面那些空章看不到内容(2026-10-08 真机反馈)。
`StructureBuilder` 的处理:**同名且尚无条文的章直接复用**(标题按去空白归一化比较),
让正文回填进目录章;该逻辑对政府网等同样带目录的正文一并生效。

### 7.3 字段映射

| 官方字段 | 应用字段 | 备注 |
|---|---|---|
| `id` | `LawRef.id`、详情页 `content.jsp?id=` 参数 | |
| `title` / `mc` | `LawRef.title` | 两者互为兜底 |
| `wh` | `LawRef.docNumber` | 如「公安部令第176号」 |
| `zlrq` / `scrq` / `publishTime` | `LawRef.publishDate` | 依次兜底 |
| `fbt` | `LawRef.effectiveDate` | 取「自YYYY年M月D日起施行」;**施行日期晚于今天是正确的** |
| `fbjg` | `LawRef.issuingAuthority` | 拼作「公安部+fbjg」;`fbjg` 为「其他」时只留「公安部」 |
| `yxx` | `LawRef.status` | `是`→现行有效,`否`→已废止 |

### 7.4 风控与克制

站点前置**创宇盾**:同一出口 IP 短时间内连续请求会被判可疑并返回 **403 HTML 拦截页**
(外观似正常响应但内容是风控提示)。应对:

- `app.mps.gov.cn` 已纳入 `HostSourceMapper` → 走 `ThrottleInterceptor`
  (同域名间隔 ≥ 2s、全局并发 ≤ 2、403/429 冷却 10 分钟);
- 单次检索最多 2 个请求(标题 + 正文),浏览无关键词时 1 个请求;
- **中文关键词编码**:官网 JS 对关键词 `encodeURIComponent` 后再被 jQuery 编码一次
  (等于编码两次)。实现不猜行为 —— 单次编码若一条都没召回且全库非空,
  才用双次编码**再试一次**,仍为空即按空结果返回;
- 契约已用实抓样本固化 `MpsRegSourceTest`,后续回归**不需要再请求官网**。

## 8. 已知限制

1. A2/A3 接口不提供时效性字段:应用对原生结果默认标记「现行有效」;权威时效性以
   国家法律法规数据库(flk)为准 —— 「今日更新」与分类页的时效性筛选对这两个源
   另加了一层**客户端兜底过滤**(源不支持该维度,只靠下推会筛出不符合条件的条目);
2. 「行政法规」分类:行政法规以国务院令公布,列表来自 A2 政策库国务院文件(国令),浏览页已标注覆盖说明;
3. 「司法解释」分类的**最高法官网**组是栏目列表(15 条/页),不含 flk 那样的官方阅读器;
   组内条目点开后由 `CourtSource.fetchDocument` 原生解析 `div.txt_txt` 的 `<p>` 正文;
4. 官网改版会导致解析失效:仅允许改 `core/parse` 并更新本文档(项目文档 8.4)。

## 9. 多源分类:按来源分组展示(2026-10-08)

「国务院及部委文件」(政府网 + 规章库)与「司法解释」(flk + 最高法)由两个官方源共同供数。
聚合层把结果并成**一条发布日期倒序列表**后,两源条目交错出现,用户只能靠卡片底部的
小徽标分辨「这条谁发的」,观感混乱、来源不可见。现改为**按来源分组**:
每组一个标题(来源名 · 条数),组内保持日期倒序。

- **组顺序 = `LawCategory.nativeSourceIds` 的声明顺序**,承载产品意图
  (官方正式文本 / 更权威的源在前),**不按条数排** —— 按条数会让这个判断随数据波动;
- 判定与实现:`LawCategory.isMultiSource` + `ui/browse/SourceGrouping`(纯函数,单测锁定);
- `SourceRegistry.nativeSourcesFor` 同步改为**按声明顺序**返回源,不再依赖注册表插入顺序
  (否则在注册表里挪一行源的位置,就会悄悄改变调用与拼接次序,极难排查);
- 分组标题与条目的 LazyColumn key 分别为 `group-<源名>` 与 `<源名>:<源内id>`,不会相撞;
- 「今日更新」是**跨来源时间线**(含「全部」视图),不做分组 —— 其语义就是「最新 N 条」。
