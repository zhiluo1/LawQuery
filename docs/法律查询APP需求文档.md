## 1. 项目背景与目标

### 1.1 背景

我国法律法规的权威发布渠道分散于多个官方网站:全国人大常委会办公厅主办的国家法律法规数据库(flk.npc.gov.cn)、中国政府网政策文件库(zhengce.www.gov.cn)、最高人民法院官网(司法解释)等。普通用户查法条时面临三个痛点:

1. **入口分散**:不知道该去哪个官网查哪类文件;
2. **权威性难辨**:搜索引擎结果混杂着大量内容农场和过期版本,难以确认条文是否现行有效、是否最新修订;
3. **手机端体验差**:部分官网移动端适配一般,无 App 化的便捷入口。

本产品做一个**纯查询工具**:不生产内容、不存储内容,只把各官方网站"实时、原样、带出处"地聚合到一部 Android 手机上。

### 1.2 产品目标

1. 让用户在 3 步以内查到任意一部法律法规的**官方现行文本**;
2. 每一条展示内容都**实时取自官方最新来源**,页面标注来源与获取时间,从机制上杜绝过期数据;
3. 严格合规:遵守各官方网站的抓取政策与使用条款,不批量采集、不镜像、不再分发。

**成功指标(首版上线后 4 周)**:

| 指标 | 目标值 |
|---|---|
| 有网环境下搜索成功率 | ≥ 95% |
| 详情页内容获取耗时 P90 | ≤ 3 秒(4G/WiFi) |
| 内容正确性投诉 | 0(机制上由官方源保证) |
| 崩溃率 | < 0.1% |

### 1.3 范围与非目标

**范围内**:搜索、分类浏览、条文详情查看、更新校验、收藏(仅元数据)、浏览历史(仅查询词)。

**非目标(明确不做)**:法律咨询与 AI 问答、付费功能、账号体系、社交功能、法条编辑批注、全文离线数据库、地方性法规全量收录(二期评估)、iOS 端(二期评估)。

## 2. 用户画像与核心使用场景

### 2.1 用户画像

| 画像 | 特征 | 核心诉求 |
|---|---|---|
| P1 普通公民 | 30–55 岁,非法务背景,遇到租房、劳动纠纷、消费维权等具体问题 | 用大白话或关键词快速找到相关法条,确认"法律到底怎么规定" |
| P2 法律从业者 | 律师、法务、公务员,高频使用 | 精确查条文编号,确认时效性(现行有效/已修订/已废止)与最新版本 |
| P3 法学生/备考者 | 备考法考、撰写论文 | 按效力位阶分类浏览、系统阅读、复制引用 |
| P4 企业合规人员 | 查国务院及部委政策文件 | 按发文机关/发文字号/日期检索政策原文 |

### 2.2 核心使用场景

**S1 关键词查条(P1,最高频)**
用户听说"离婚冷静期" → 打开 App 输入关键词 → 结果页展示相关法律及来源 → 进入《民法典》官方页面 → 定位第 1077 条 → 复制条文文本。

**S2 确认时效性(P2)**
律师开庭前需确认某条例是否仍有效 → 搜索标题 → 结果项带时效性徽标"现行有效" → 进入详情核对公布日期、施行日期与修订版本。

**S3 分类浏览(P3)**
法学生想系统学习 → 首页进入"法律"分类 → 按公布日期浏览现行有效法律列表 → 打开某部法律逐条阅读,使用目录跳转和字号调节。

**S4 查政策文件(P4)**
合规人员查"数据安全"相关政策 → 搜索 → 在国务院政策文件库结果中按发文机关筛选 → 打开原文核对发文字号。

**S5 收藏跟进修订(P2)**
用户收藏了《公司法》 → 某日打开收藏,列表显示"已更新"徽标(官方源元数据与收藏时不一致) → 点击查看最新版本。

## 3. 总体方案:多官方数据源与合规接入策略

### 3.1 设计原则

1. **官方源唯一**:内容只来自政府官方网站,展示时必须标注来源与原文链接;
2. **实时获取**:每次查看均联网拉取,不落盘、不缓存过期数据(唯一例外:内存会话缓存,TTL ≤ 5 分钟,见 6.1);
3. **多源冗余**:单一来源受限或故障时,自动降级到其他官方源或"官方直通"模式,保证功能不中断;
4. **合规优先**:某源禁止程序化采集时,改用 App 内置受控 WebView 让用户直接浏览官方页面(App 等同浏览器的角色),不解析、不存储、不篡改。

### 3.2 数据源清单与接入模式

| 优先级 | 来源 | 主办方 | 覆盖范围 | 抓取政策(2026-10-04 核实) | 接入模式 |
|---|---|---|---|---|---|
| A1 | 国家法律法规数据库 flk.npc.gov.cn | 全国人大常委会办公厅 | 宪法、法律、行政法规、监察法规、司法解释、地方性法规,**最全最权威** | robots.txt 明确"禁止任何自动化工具、脚本、爬虫采集",全站 Disallow;站点 JS 渲染,接口有动态签名 | **受控 WebView 直通**(用户实时浏览官方页面),App 不解析、不存储其内容 |
| A2 | 中国政府网政策文件库 zhengce.www.gov.cn | 国务院 | 国务院文件、行政法规(国务院令)、部委文件 | robots.txt 宽松(向搜索引擎开放并提供 sitemap,仅个别路径禁抓) | **原生解析**(HTML→结构化),低频访问 |
| A3 | 最高人民法院 www.court.gov.cn | 最高人民法院 | 司法解释、司法文件 | 无 robots.txt(无声明性限制) | 原生解析,低频,遵守网站条款 |
| A4 | 最高人民检察院 www.spp.gov.cn | 最高人民检察院 | 检察司法解释 | M0 阶段核实 | 预留 Source 接口,核实后接入 |
| B1 | 各省人大官网 | 省级人大常委会 | 地方性法规 | 逐省差异大 | 二期评估,首版不做 |

> 以上 robots.txt 结论须在 M0 阶段与每次发版前复核;若政策变化,按"原生解析 → WebView 直通 → 移除该源"顺序降级处理。

### 3.3 双通道架构

- **通道一 原生解析通道(可解析源 A2/A3)**:App 请求官方页面 HTML → 服务端解析为结构化数据(标题、元信息、条文列表)→ 原生界面渲染,体验好,可做条内定位、复制、收藏校验。请求仅在用户主动触发时发出。
- **通道二 官方直通通道(受限源 A1 等)**:受控 WebView 组件加载官方页面,原生壳仅提供:标题栏(显示来源域名)、加载进度、刷新、分享原文链接、在系统浏览器打开。**不注入修改内容的 JS,不截取 DOM,不读取页面数据。** 官方页面的搜索、浏览均在页内完成,内容天然实时。

### 3.4 降级链路

```
用户搜索/浏览
 ├─ A2/A3 原生解析 → 成功 → 原生结果列表/详情
 │                    └─ 失败(403/429/超时/改版) → 重试 1 次(指数退避)→ 仍失败 → 从本次结果中剔除并提示"该来源暂不可用"
 └─ A1 官方直通 → WebView 加载 → 成功 → 用户在官方页面内完成搜索与阅读
                                 └─ 加载失败 → 错误页 + 重试 / 跳转系统浏览器
全部来源不可用 → 统一网络异常页(见 F7)
```

## 4. 功能需求

优先级定义:P0 首版必须;P1 首版尽量;P2 二期。所有页面的加载/空/错误/离线状态遵循 F7。

### F1 搜索(P0)

| 项 | 内容 |
|---|---|
| 入口 | 首页顶部搜索框,点击进入搜索页,自动弹起键盘 |
| 输入 | 关键词(法律名称、条文内容词、发文字号、朴素用语均可);输入停顿 300ms 后发起联想(联想仅基于本地历史,P1) |
| 执行 | 一次搜索并行查询:① A2/A3 原生解析源(原生结果列表);② A1 官方直通(结果页顶部固定一张卡片:"在国家法律法规数据库中搜索『关键词』",点击进入 WebView 并自动定位到官方搜索结果) |
| 原生结果项 | 标题(命中词高亮)、发文字号、发文机关、发布日期、时效性徽标、来源标识 |
| 筛选(P1) | 效力位阶、发文机关、发布日期区间、时效性(现行有效/已修订/已废止/尚未生效) |
| 排序 | 默认相关度;可切换发布日期倒序 |

### F2 分类浏览(P0)

| 项 | 内容 |
|---|---|
| 首页分类入口 | 宪法、法律、行政法规、监察法规、司法解释、地方性法规、国务院及部委文件(每项显示可服务的来源标识) |
| 数据路由 | 每个分类在 M0 确定数据源映射:可原生解析的 → 原生列表页;仅 A1 覆盖的 → 进入该分类的 WebView 官方直通页 |
| 原生列表页 | 按发布日期倒序;筛选:时效性、发文机关、年份;滚动分页 |
| 列表项 | 与 F1 原生结果项相同 |

### F3 条文详情(P0)

**原生详情页(来自可解析源)**:
- 元信息区(置顶常显):标题、发文字号、制定/发文机关、公布日期、施行日期、时效性徽标、**来源名称 + 原文链接 + "获取于 YYYY-MM-DD HH:mm"**;
- 正文区:按 章 → 节 → 条 层级渲染;长文按章懒加载,默认折叠到目录态(防止民法典级别长文一次渲染卡顿);
- 条内操作:点击任意条 → 弹出操作条(复制本条 / 分享本条文本);分享内容自动附带"来源:××官网 原文链接";
- 目录抽屉:按章/节导航,支持输入条号(如"1077")直达并高亮;
- 字号调节:5 档,全局记忆;
- 顶部"在官方源查看原文"按钮,跳 WebView 直通页(给需要核对 PDF 公报的用户)。

**WebView 直通详情页(来自受限源 A1)**:
- 原生壳:标题栏显示"国家法律法规数据库 · 官方页面"、加载进度条、刷新、分享链接、系统浏览器打开;
- 页面加载前后显示"以下为官方页面实时内容"横幅提示;
- 不可用时的错误页与重试;
- 禁用文件访问与未知域名跳转(白名单见 7.4)。

**附件(P2)**:官方源提供公报 PDF 链接时,提供"查看官方 PDF"跳转系统浏览器或系统下载。

### F4 更新校验(P0,详见第 6 章)

- 详情页内容每次进入均实时拉取,永不读取磁盘旧正文;
- 收藏项打开前先拉取最新元数据,与收藏时记录的版本指纹比对,不一致则提示"该文件已更新,点击查看最新";
- 冷启动时后台串行校验收藏列表元数据(限流执行),列表项显示"已更新"徽标;
- 详情页常显"获取于"时间戳;校验失败(网络错误)绝不展示旧内容冒充新内容。

### F5 收藏与历史(P1)

- 收藏对象:文件元数据(id、标题、来源、原文链接、收藏时的发文字号/公布日期/施行日期/时效性指纹)。**不存正文**;
- 收藏列表:按收藏时间倒序,显示标题、来源、时效性、"已更新"徽标;支持分组/搜索(P2);
- 历史:仅查询词(见 F1),与"最近浏览"列表(仅元数据,最多 50 条)。

### F6 设置与关于(P1)

- 阅读:默认字号、深色模式跟随系统;
- 数据源:各来源清单、健康状态(最近一次请求结果)、政策说明;
- 关于:版本、开源许可、**免责声明**(文案见 7.2)、隐私政策(零收集声明);
- 清除数据:清空历史/收藏。

### F7 通用状态规范(P0)

| 状态 | 表现 |
|---|---|
| 加载中 | 骨架屏(列表)/居中进度(详情),超 8 秒提示"官方源响应较慢,可稍后重试" |

| WebView 失败 | 错误页 + 重试 + "在系统浏览器打开" |

## 5. 技术栈与架构

### 5.1 选型决策

**采用 Android 原生(Kotlin + Jetpack Compose),不采用 Flutter。** 理由:

1. 目标仅 Android 单端,无跨端收益;
2. 本产品的两个核心技术点——**受控 WebView 容器**(白名单、安全配置、进度/错误接管)与**网络层精细控制**(禁用磁盘缓存、限流、指数退避、条件请求)——在原生 OkHttp/WebView 上控制粒度最好;
3. 超长法条文本渲染(数千段)Compose LazyColumn 直接胜任;
4. 无需任何原生插件桥接,vibecoding 排错链路最短。

### 5.2 技术栈清单

| 层 | 选型 | 说明 |
|---|---|---|
| 语言/构建 | Kotlin 2.x、JVM 17、Gradle KTS + Version Catalog | 单模块起步 |
| UI | Jetpack Compose + Material 3、单 Activity + Navigation Compose | MVVM,`UiState` 密封状态驱动(F7 的状态即 UiState) |
| 状态 | ViewModel + StateFlow + kotlinx.coroutines | |
| 网络 | OkHttp + Retrofit;gov.cn 源 HTML 直取(接口若存在则优先,M0 探明) | 自定义拦截器:统一 UA(真实浏览器 UA + 应用标识)、限流器(全局并发 ≤ 2,同源间隔 ≥ 2s)、退避重试(最多 1 次)、禁用磁盘缓存 |
| 解析 | Jsoup(HTML→结构化)→ 领域模型;kotlinx.serialization(JSON 场景) | 解析器与模型解耦,页面改版只改 Parser 层 |
| WebView | 系统 WebView + 受控封装 | 安全配置见 7.4 |
| 本地存储 | Room(收藏/最近浏览/源健康状态,均为元数据表);DataStore(设置) | **无任何正文表** |
| DI | 手动 DI(AppContainer) | 规模小,不引入 Hilt 降低 vibecoding 复杂度 |
| 测试 | JUnit + MockWebServer(解析器/限流器单测)、Compose UI Test、手工真机矩阵 | |

### 5.3 分层与项目结构

```
com.lawquery/
  core/net/        // OkHttp 单例、限流拦截器、退避、源健康上报
  core/parse/      // GovCnParser、CourtParser → LawDocument
  data/source/     // LawSource 接口 + GovCnSource / CourtSource / WebOnlySource(flk,仅产出"官方直通"跳转信息)
  data/repo/       // SearchRepository / LawDetailRepository / FavoriteRepository
  data/local/      // Room(收藏、最近浏览、源健康) + DataStore(设置)
  domain/model/    // LawRef / LawArticle / LawDocument / VersionFingerprint
  ui/
    home/ search/ browse/ detail/ web/ favorites/ settings/ common/
  di/              // AppContainer 手动装配
```

**领域模型(核心)**:

```kotlin
data class LawRef(          // 列表项/元数据(可入库,即"版本指纹")
  val id: String,           // 源内唯一 id
  val title: String,
  val issuingAuthority: String,   // 制定/发文机关
  val docNumber: String?,         // 发文字号
  val publishDate: LocalDate?,    // 公布日期
  val effectiveDate: LocalDate?,  // 施行日期
  val status: LawStatus,          // CURRENT有效 / REVISED已修订 / REPEALED已废止 / PENDING尚未生效
  val source: LawSourceId,        // GOV_CN / COURT / FLK_WEB / ...
  val url: String,                // 官方原文链接
)

data class LawDocument(     // 详情(仅内存,禁止入库)
  val ref: LawRef,
  val fetchedAt: OffsetDateTime,  // 获取时间,详情页常显
  val preamble: String?,
  val chapters: List<Chapter>,    // 章→节→条
)
```

### 5.4 数据流(以详情页为例)

`UI 事件 → ViewModel → LawDetailRepository.getLaw(ref)`:
1. 命中内存会话缓存且 TTL 未过期 → 直接返回(带原 fetchedAt);
2. 否则 `LawSource.fetchDocument(ref)` → 网络/解析 → 返回 `LawDocument` 并写入会话缓存;
3. 结果映射为 UiState(Loading / Success / Empty / Error / Offline)渲染;
4. 任何路径都不会读取磁盘正文——磁盘里根本没有正文表。

## 6. 数据同步与更新校验策略(核心机制)

### 6.1 缓存策略(严格执行)

| 层 | 策略 |
|---|---|
| HTTP 磁盘缓存 | **禁用**(OkHttp 不配置 Cache,`Cache-Control: no-cache` 请求头),确保每次进入页面都是对官方源的实时请求 |
| 内存会话缓存 | `LruCache<String, SessionEntry>`,容量 ≤ 20 个文档,TTL 5 分钟;仅用于返回上一屏的瞬时恢复;条目必须携带 `fetchedAt` 并在 UI 展示;进程结束即消失 |
| Room | 仅元数据:收藏、最近浏览(≤50 条)、源健康状态、历史查询词 |
| WebView | 不做任何离线快照;系统 WebView 自身的 HTTP 缓存遵循官方源响应头 |

### 6.2 版本指纹与更新校验

- **指纹定义**:`{发文字号, 公布日期, 施行日期, 时效性}`,取自官方源元数据;
- **收藏时**:记录当时的指纹;
- **打开收藏时**:实时拉取最新元数据 → 与本地指纹比对 → 一致:直接进入详情;不一致:弹提示"该文件已有更新(公布日期:××),查看最新版本",并更新本地指纹;
- **冷启动**:后台协程串行校验所有收藏项的元数据(仅轻量元数据请求,间隔 ≥ 2 秒,失败静默跳过),结果驱动收藏列表"已更新"徽标;
- **详情页**:无论何种入口,内容均按 6.1 实时获取,页面常显"来源:×× · 获取于 HH:mm"。

### 7.1 性能

| 冷启动(中端机,如骁龙 7 系/Android 12) | ≤ 2s 到首页可交互 |

| WebView 直通页可交互 | ≤ 4s(P90,受官网速度影响,展示进度条) |
| 列表滚动 | 无可感知掉帧 |
| 内存峰值(渲染民法典级别长文) | ≤ 300MB |
| APK 体积 | ≤ 30MB |
| 崩溃率 / ANR | < 0.1% / < 0.05% |

### 7.2 合规(红线清单)

1. **遵守 robots.txt 与网站条款**:各源政策以 3.2 表为准并定期复核;政策变化时按 3.4 降级。对 flk.npc.gov.cn **永不**做程序化解析或采集,仅 WebView 浏览;
2. **不绕过防护**:不破解签名/验证码/加密,不伪造 Cookie,不使用代理池轮换 IP;UA 如实标识;
3. **访问节律**:仅在用户主动操作时发起请求;全局并发 ≤ 2;同一源请求间隔 ≥ 2s;收到 403/429 立即停止对该源请求并退避 ≥ 10 分钟,期间该源标记"暂不可用"并走降级;
4. **不批量、不镜像、不再分发**:不做定时全量抓取,不构建本地法规库,不向第三方提供数据接口;
5. **来源标注**:所有原生列表项与详情页显著标注来源官网名称与原文链接;分享文案自动附带来源;
6. **内容权利**:法律法规官方文本依《著作权法》第五条不适用著作权保护;官方公报 PDF 的版式排版归官方,App 仅提供链接跳转,不复制不重排;
7. **免责声明(固定文案,关于页 + 首次启动弹窗)**:"本应用是官方法律法规网站的查询工具,所展示内容均实时来自各官方网站,仅供参考,请以官方公布文本为准。若内容显示异常,请点击'查看原文'访问官方网站。";
8. **个人信息**:不采集任何个人信息;不申请与功能无关权限(仅 `INTERNET`,分享/复制走系统能力不单独申请权限);无账号、无第三方统计 SDK;隐私政策明示"零收集";
9. **上架合规(如发行)**:完成工信部 App 备案;应用商店隐私检测通过。

### 7.3 离线策略

与"不缓存过期数据"原则一致,离线是**明确的能力边界**而非功能:

- 无网络:搜索/浏览/详情一律进入 F7 统一离线页,不展示任何正文;
- 可离线使用的仅元数据:收藏列表、最近浏览列表、历史查询词(点开仍需联网);
- 网络恢复自动重试当前操作;
- 不提供"离线包下载"类功能(与产品原则冲突,不做)。

### 7.4 安全

- 全局禁用明文流量(`usesCleartextTraffic=false`),仅 HTTPS;
- WebView:`javascriptEnabled=true`(官网需要)但 `allowFileAccess=false`、`allowContentAccess=false`;URL 白名单:`flk.npc.gov.cn`、`*.www.gov.cn`、`www.gov.cn`、`www.court.gov.cn`(跳转其他域名时拦截并提示"即将离开官方来源",仅允许在系统浏览器打开);
- 解析层输出纯文本 + 受控结构,原生渲染无 HTML 注入面;分享/复制内容为纯文本。

### 7.5 兼容与无障碍

- Android 8.0–最新(API 26+),覆盖手机和平板主流分辨率;
- 深色模式跟随系统;
- 无障碍:全部控件 contentDescription;正文支持系统字号缩放(TalkBack 可用);
- 中文简体(首版唯一语言)。
